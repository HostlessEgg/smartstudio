# Reporte de concordancia vs requisitos (SMARTSTUDIO LMS)

Fecha: 2026-02-04

## Alcance revisado
- Backend principal con múltiples endpoints: `backend/server.js`.
- Backend alterno minimalista: `backend/src/app.js` (duplicidad).
- Frontend: pantallas amplias, varias conectadas a mock API.
- Base de datos: esquema amplio con entidades clave.

## Evaluación por requisito (actualizada)

### 1) Gestión de usuarios y roles
- **Evidencia**: endpoints de listado/edición/roles/bulk/CSV; tabla `users`.
- **Estado**: **Casi completo**.
- **Faltante**: desactivación individual y auditoría completa de creación/modificación.
- **Desajuste**: roles requeridos (`Instructor`, `Estudiante`) vs enum actual (`teacher`, `student`).

### 2) Gestión de cursos
- **Evidencia**: endpoints CRUD + estado; tablas `courses` y `course_versions`.
- **Estado**: **Parcial**.
- **Faltante**: versionado real (tabla sin uso), reglas de publicación avanzadas.

### 3) Estructura de contenidos
- **Evidencia**: creación de módulos/lecciones al crear curso; endpoint de lectura.
- **Estado**: **Parcial**.
- **Faltante**: reordenado con API, recursos SCORM/externos, control de acceso por inscripción.

### 4) Inscripción y cohortes
- **Evidencia**: inscripción directa, auto-enroll, CSV; cohortes + importación.
- **Estado**: **Parcial/Bueno**.
- **Faltante**: CRUD completo de cohortes, reglas avanzadas y visibilidad.

### 5) Evaluaciones
- **Evidencia**: quizzes + submissions + grading; uploads S3/local.
- **Estado**: **Parcial/Bueno**.
- **Faltante**: rúbricas, intentos máximos, límites de tiempo, feedback formalizado.

## Extras agregados (no en requisitos)
- Foros, curriculum, feature flags, notificaciones, representantes/consentimientos.

## Riesgos
- Duplicidad de backend (`server.js` vs `src/app.js`).
- UI aún usa mock API en varias rutas.

## Conclusión
- Concordancia conceptual: **media/alta**.
- Cumplimiento funcional: **medio** (MVP casi alcanzado, faltan piezas clave).
